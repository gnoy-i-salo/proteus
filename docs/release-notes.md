# PROTEUS 0.3.0

Черновик релиза с подключениями Telegram, VK, GitHub и Instagram, выбором источников для каждой персоны и сохранением авторского стиля. Установщики и контрольные суммы добавляются в GitHub Release только после полного gate и сборки всех четырёх платформ. Workflow оставляет релиз черновиком.

## Подключения и источники

- В настройках появился раздел «Подключения». Telegram проходит нативные этапы входа через TDLib: телефон, код, пароль, при необходимости email. VK использует браузерный вход с возвратом через опубликованную страницу и `proteus://`; GitHub — device flow. Статус «Подключено» появляется только после ответа нативного адаптера.
- Пользователь задаёт собственные API ID / API hash Telegram и Client ID VK / GitHub. Секретные поля очищаются после отправки нативному приложению; токены не сохраняются в браузерном хранилище и не включаются в пресеты.
- Для Instagram доступен импорт JSON / текстового экспорта и подключение своего Business / Creator аккаунта по действующему API-токену. Личный аккаунт не получает через официальный API доступ к произвольным чужим страницам и переписке. ZIP требуется предварительно распаковать.
- Для каждой персоны явно выбираются ресурс, автор, даты и разрешение на обработку моделью. До пяти источников на персону; начальные пределы каждого — 1000 документов, 1 МиБ, 40 действий и 5 минут. Нативный адаптер проверяет разрешение и сообщает фактическое покрытие, недоступность и усечение.
- Доступ к выбранным источникам не переносится в `.proteus` v1. Смена пресета или модели STALKER снимает прикреплённые разрешения. Отключение аккаунта удаляет локальный доступ; отзыв OAuth-разрешения у сервиса выполняется отдельно. «Удалить материалы STALKER» удаляет выбранный корпус и checkpoints, сохраняя подключение; это не удаление отдельной базы TDLib.

## Персона и результаты

STALKER собирает только выбранный диапазон и отделяет текст источника от инструкций. Свидетельства и гипотезы сохраняют происхождение и ограничения. Наблюдаемые особенности речи, контекст общения, точные образцы и исключённые проверочные материалы используются отдельно; стиль не считается доказательством характера, интеллекта или способностей человека.

Ответ персоны сохраняет отдельные сообщения, пробелы, пунктуацию и переносы строк. Интерфейс выводит текст без исполнения HTML и показывает пометку о поведенческой симуляции отдельно от сообщения. Пагинация сохраняет исходный текст.

Новые результаты используют `schema-version: 3`, `scoring-version: 2` и протокол `bsc-v2.2-source-style`. Экспорт и нативное сохранение проходят общий фильтр: материалы, не разрешённые для экспорта, не переносятся в JSON и файлы персоны. Исторические результаты не переписываются. BSC остаётся экспериментальной оценкой выполнения задачи по рубрике, а не мерой интеллекта человека.

## Текущие ограничения

- Для эксперимента с подключёнными источниками требуется Codex во всех компонентах. Kimi остаётся доступным для обычных экспериментов; обработка подключённых материалов через Kimi отключена до поддержки изолированного запуска без пользовательских hooks. Настройки не меняются автоматически.
- Реальные входы и чтение через Telegram, VK, GitHub и Instagram не проверены на пользовательских аккаунтах в этой подготовке релиза. Доступ зависит от регистрации приложения, выданных разрешений, типа аккаунта и ограничений платформы; успешный вход не обещает чтение всех данных.
- Импорт поддерживает реализованные JSON-схемы и подготовленный текст. Неподдерживаемый формат возвращает ошибку; вложения и недоступная история не восстанавливаются автоматически.
- Изучение источника ограничено выбранным ресурсом и бюджетом. Отчёт о полноте не означает достоверность всех исходных утверждений или точность модели реального человека.

## Проверки и сборка

Проверены состояния входа через имитацию нативного IPC, очистка секретных полей, отсутствие ложного подключения в браузере, разрешение выбранного источника, ограничения моделей, отдельные сообщения и вывод разметки как текста. Проверяются клавиатурное управление и размещение в окне 640×600. Эти проверки не заменяют вход в реальный аккаунт.

Локально пройден полный набор из 53 браузерных сценариев приложения и страницы возврата авторизации. Полный `pnpm check` прошёл: тесты, 16 harness-проверок, типы, линтеры, FSD, LikeC4 и production-сборки обоих приложений. `pnpm check:rust` прошёл с включённой TDLib; после последнего исправления обновления токенов подтверждены 47 успешных Rust-тестов. Один существующий live CLI тест исключён из обычного набора, поскольку использует реальные аккаунты. Отдельный синтетический запрос установленному Codex с точными флагами изоляции выполнен успешно.

TDLib собирается из закреплённой официальной ревизии после проверки SHA-256; она включается в нативное приложение. macOS Intel собирается на Intel runner, Apple Silicon — на ARM runner. Windows использует статическую zlib с совместимой динамической CRT. Лицензии включены в пакет.

GitHub workflow прикрепляет установщики и `SHA256SUMS.txt` только после успешных проверок и сборок всех четырёх платформ. Публикация пользователям выполняется отдельным действием после проверки черновика.

## Установка

Приложение использует отдельно установленные и авторизованные Codex / Kimi CLI. Установщики: macOS Apple Silicon и Intel (`.dmg`), Windows x64 (`.exe`), Linux x64 (`.deb`, Ubuntu 24.04 и совместимые системы). `SHA256SUMS.txt` содержит контрольные суммы всех четырёх установщиков.

macOS подписан ad-hoc без Apple notarization; Windows — без сертификата издателя. Данные и настройки приложения хранятся отдельно от установщика.

Предыдущая опубликованная версия: [PROTEUS 0.2.0](https://github.com/gnoy-i-salo/proteus/releases/tag/v0.2.0), перевод сравнения персон на BSC v2. Её проверки и опубликованные установщики относятся к версии 0.2.0.

Локальная release-сборка macOS Apple Silicon с встроенной TDLib и упаковка `.app` / `.dmg` прошли. Динамические зависимости бинарника — системные библиотеки macOS; отдельная установленная TDLib не требуется.
