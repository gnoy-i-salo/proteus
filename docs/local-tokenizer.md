# Локальный токенизатор E5

`e5-tokenizer.rs` читает только явно переданный локальный файл. Он не скачивает
модель, не вызывает сеть и не выполняет embedding inference. Это подготовительный
компонент tip.8/tip.10; выбор embedding runtime, RU dialogue benchmark и индекс
остаются отдельными условиями приёмки.

Закреплён кандидат [intfloat/multilingual-e5-small](https://huggingface.co/intfloat/multilingual-e5-small/tree/614241f622f53c4eeff9890bdc4f31cfecc418b3)
(MIT по upstream model card). Используется
[onnx/tokenizer.json](https://huggingface.co/intfloat/multilingual-e5-small/resolve/614241f622f53c4eeff9890bdc4f31cfecc418b3/onnx/tokenizer.json)
из commit `614241f622f53c4eeff9890bdc4f31cfecc418b3`:

- Размер: `17082730` байт.
- SHA256: `0b44a9d7b51c3c62626640cda0e2c2f70fdacdc25bbbd68038369d14ebdf4c39`.
- Runtime токенизации: `tokenizers = 0.23.2`, без default features и HTTP, с `fancy-regex`.
- Для документов применяется точный префикс `passage: `, для запросов — `query: `;
  специальные токены включены в подсчёт. Ограничение model input: 512 токенов.
- Сохранённые настройки truncation/padding отключаются. Подсчёт для chunking
  возвращает полную длину; model input сверх окна отклоняется, а не обрезается.
- Fingerprint включает upstream commit, SHA256, runtime и версии templates/special
  tokens. Исходный текст и диапазоны корпуса не нормализуются этим адаптером.

Перед native-проверками и сборкой выполняется `pnpm prepare:models`. Команда
получает публичный tokenizer package в игнорируемый `.cache/models`, проверяет
размер/SHA256 из `scripts/e5-package.json` и атомарно устанавливает только полный
проверенный файл. Повреждённый существующий cache не перезаписывается. Ошибка HTTP,
оборванный ответ или превышение размера удаляют временный файл, не создавая пакет.

Этот же pin читается Rust build script и runtime. Native build останавливается
при отсутствии или повреждении файла. Tauri включает его как
`models/e5-tokenizer.json` в ресурсы всех четырёх платформ; CI и Release готовят
пакет явно перед native gates. Приложение само не скачивает файлы модели.
Attribution и лицензия входят в `third-party-notices.txt`.

Публичный loader принимает только закреплённый файл. Отсутствие файла, другая
длина, checksum или повреждённый JSON дают явную ошибку. Файлы модели не хранятся
в Git. Полноценный FTS-only режим при отсутствии embedding weights реализуется
владеющим runtime, а не подменой токенизатора подсчётом символов.

Проверка на самостоятельно скачанном публичном tokenizer file:

```sh
cargo run --locked --manifest-path apps/desktop/src-tauri/Cargo.toml \
  --example e5-tokenizer-check -- /absolute/path/to/tokenizer.json
```

Пример проверяет точные token IDs русских строк, многоязычный подсчёт и отказ
при превышении окна, затем печатает время загрузки и p50/p95 для 100 подсчётов
одного синтетического текста. Эти числа относятся только к токенизации и не
измеряют embedding latency, RAM модели или качество retrieval. Unit fixtures
используют маленький синтетический словарь; они не заменяют эту проверку E5.

Native-команда `prepare_ingestion_job` принимает versioned metadata: operation ID,
job ID и бюджет времени. Путь ресурса, политика split и исходные сообщения не
принимаются от frontend. Подготовка использует интервалы 30 минут, 20% holdout,
seed `proteusReferenceHoldout:1`, окно 512 токенов и 64 KiB на чанк. Значения входят
в fingerprint; это начальная воспроизводимая политика, а не измеренная оптимальность.

Время загрузки токенизатора учитывается в бюджете. Результат — отдельный снимок
с версиями эпизодов, без завышения indexed/analyzed/used coverage. TS
`CorpusPreparationPort` отклоняет чужой или неподготовленный ответ и подтверждает
отмену операции без отмены завершённого импорта. Экран подготовки и runtime
retrieval ещё подключаются отдельно.

Подготовленный снимок теперь можно передать нативному сценарию
`ingestion::search::rebuild`. Он последовательно читает только reference-чанки,
проверяет точный UTF-8 span оригинала и извлекает persona/grant/binding из текущей
задачи. Строгий декодер источника повторно проверяет принадлежность сообщения
выбранной области. Разрешения проверяются перед каждой страницей; общая блокировка
источников освобождается между страницами. Размер страницы ограничен 100 чанками
и 64 MiB сохранённых JSON/оригиналов, с общими ссылками на повторяющиеся оригиналы.
Полный манифест проверяется в начале и перед публикацией, а не для каждого чанка.

Индекс хранится в том же SQLCipher и переключает поколение атомарно. Отмена,
истечение времени или разрешения откатывают незавершённую публикацию, сохраняя
прежнее поколение. Новый rebuild владеет отдельным этапом; повторный успешный
rebuild создаёт новое поколение. Он не переписывает raw receipt и не объявляет
исходные данные проанализированными. При первом открытии базы SourceStore удаляет
оставшиеся после прошлого процесса незавершённые этапы `nativeFts:` страницами
по 100 записей. Текущие рабочие операции ещё не получили соединение. Повторное
чтение той же базы не запускает очистку; чужие этапы и опубликованные receipts
сохраняются. Каждая страница удаляется атомарно вместе с временными FTS-строками,
ошибка откатывает страницу и допускает повтор после открытия. Возраст этапа не
используется как доказательство его завершения.

`ingestion::search_query::query` выполняет локальный поиск для персоны из
сохранённой задачи. Фронтенд не назначает пары grant/binding: сценарий выводит
их из текущих разрешений, проверяет владельца подготовленного снимка, политику
разбиения/токенизатора и полноту индекса. Для продолжения страницы нужен ожидаемый
номер поколения; перестроенный индекс требует начать поиск заново. Полная
публикация индекса сравнивается внутри той же транзакции чтения, что и FTS-запрос.
Перед возвратом повторно проверяются задача, разрешения, бюджет и текущая публикация;
удаление источника после поиска также отклоняет найденные ссылки. Выход сохраняет
revision и UTF-8 byte spans; разрешение корпуса не заменяет разрешения модели/экспорта.

Лимит времени запроса — до 60 секунд; отмена и срок проверяются до/после SQL
и во время проверки метаданных. Текущий SQLite sort не прерывается посередине:
просроченный результат отклоняется после его завершения. Это кооперативный бюджет,
не гарантия жёсткого времени завершения SQL. IPC поиска и MemoryPort ещё не подключены.
FTS не требует embedding weights, но использует уже подготовленные
чанки с закреплённой версией токенизатора. Лексический поиск не исправляет
опечатки и не приравнивает `ё` к `е`; исходный текст сохраняется точно.

Очередь и область одного FTS-запроса используют общий предел 1024 привязки.
Поиск принимает весь допустимый выбор; 1025 привязок или grants отклоняются,
а не молча обрезаются. Разрешённая пара в конце большого списка не теряется;
порядок результатов и пагинация сохраняются.
