# Выбранная публичная страница

`ingestion::selected_page::fetch` — нативный загрузчик одной явно выбранной страницы для
`proteus-tip.7`. Это слой получения исходника; подключение к durable ingestion, сохранение
снимка URL и UI ещё не завершены. Текстовая проекция HTML
реализована отдельно в `selected_page_content`; сохранённые локальные страницы уже
проходят общую очередь, как описано ниже.
Текущий загрузчик сам не вызывает модель, не обходит ссылки и не приписывает авторство
страницы владельцу сайта или выбранной Персоне.

Принимаются HTTP/HTTPS на стандартных портах, без встроенных учётных данных. Каждый
переход проверяется заново: не более пяти перенаправлений, без перехода с HTTPS на HTTP.
Проверка DNS отклоняет весь ответ, если хотя бы один адрес относится к локальным,
частным, служебным, документационным или неподдерживаемым диапазонам. IPv6 ограничен
глобальным unicast с исключением специальных и переходных диапазонов. Политика намеренно
консервативнее доступности отдельных специальных адресов. Используются
[реестр IPv4 IANA](https://www.iana.org/assignments/iana-ipv4-special-registry/) и
[реестр IPv6 IANA](https://www.iana.org/assignments/iana-ipv6-special-registry/).

Проверенные IP закрепляются в новом HTTP-клиенте для конкретного перехода с сохранением
имени сервера для TLS; адрес фактического соединения также проверяется. Автоматические
redirects, proxy, Referer и распаковка отключены. Нет cookies и заголовков авторизации,
нет обращения к хранилищам аккаунтов. Настройки клиента соответствуют API
[reqwest 0.12 blocking ClientBuilder](https://docs.rs/reqwest/0.12.28/reqwest/blocking/struct.ClientBuilder.html).

Размер ограничен максимумом 16 MiB, включая ответы без Content-Length или с ложным
значением; объявленный и фактический размеры должны совпасть. Принимается только полный
ответ 200 с `text/html`, `text/plain` или `text/markdown` и UTF-8. Неизвестная кодировка,
сжатие, частичный ответ, HTTP-ошибка и повреждённый UTF-8 завершаются явной ошибкой.
Исходные UTF-8 байты, пробелы, CRLF, Unicode и HTML сохраняются без нормализации. SHA256
вычисляется по этим байтам; снимок содержит исходный выбранный URL, конечный URL, цепочку
перенаправлений и время получения. Фрагменты URL не отправляются серверу. HTML нельзя
непосредственно вставлять в интерфейс как разметку.

Бюджет одного получения — до 60 секунд, охватывает разрешение имени, переходы и чтение.
Текущий остаток передаётся сетевому клиенту, проверяется до/после I/O и перед возвратом
результата. Отмена кооперативная: уже ожидающий сетевой вызов не прерывается мгновенно;
просроченный или отменённый результат не возвращается. Системный DNS не имеет переносимой
принудительной отмены: ожидание ограничено, одновременно допускаются не более двух
DNS-работников, и просроченный работник удерживает слот до своего завершения.

Проверка grant, разрешения на модельную обработку и export остаётся обязанностью сценария,
который будет сохранять и использовать снимок. Этот транспорт не выдаёт grant и не заменяет
проверку прав. Для login-only страниц предусмотрен отдельный импорт; данный загрузчик не
использует активную браузерную сессию. Модельные и личные архивы в тесты не передаются.

Синтетические тесты покрывают ограничения адресов и mixed DNS, повторную проверку после
redirect, смену DNS-ответа, предел переходов, ложный размер, тип/кодировку/status,
сохранение точного текста и происхождения, отмену после DNS и во время чтения, общий
deadline. Они не являются живой проверкой произвольных сайтов или завершением задачи
`proteus-tip.7`.

## Текстовая проекция

`selected_page_content::extract` использует закреплённые `dom_query 0.28.0` и
`html5ever 0.39.0`, уже присутствовавшие в lockfile. Версия преобразования —
`selectedPageText:1:domQuery0.28.0:html5ever0.39.0`; `page_document` фиксирует её вместе с оригиналом. Plain text и Markdown возвращаются побайтово без
интерпретации разметки. Для HTML создаётся отдельный текст: entities декодируются,
CRLF обрабатываются по HTML-правилам, между блочными элементами добавляются переносы.
Внутренние пробелы, табуляция, слова и Unicode не схлопываются. Это проекция, а не
замена исходных HTML-байтов или карта смещений в raw HTML.

В текст не входят script/style/template/iframe/object/embed/SVG/MathML и поддеревья
с `hidden` либо `aria-hidden=true`. Код и ссылки не выполняются и не загружаются.
CSS-layout не вычисляется: результат не объявляется копией видимого браузерного экрана.
Страницы с password-input отклоняются как потенциальная форма входа; скриптовая страница
без статического текста также завершается явной ошибкой.

Title и author labels берутся из исходной разметки без назначения ID автора или Персоны.
Метка `publisherMetadataUnverified` отделяет их от подтверждённой идентичности. Дата
принимается только из единственного однозначного RFC3339 `article:published_time`;
неизвестная/ошибочная/противоречивая дата остаётся `null` и не заменяется временем загрузки.
Исходные metadata сохраняются в оригинале. Роль и право приписывать собственные слова
проверяются отдельно при создании source binding.

Вход и выход ограничены 4 MiB; предварительная консервативная граница — 20000 символов
`<`, включая комментарии и атрибуты. HTML подаётся парсеру порциями до 4096 байт с
проверками отмены между ними. Обход ограничен 100000 событиями и глубиной 256; metadata —
32 уникальных значения по 2048 байт. Превышение даёт ошибку, а не неполный успешный текст.
Отмена внутри одного вызова HTML-парсера кооперативная. Восстановление ошибочной разметки
явно отмечается `htmlMarkupRepaired`; парсер не удостоверяет правдивость текста страницы.

Используется стандартный [HTML DOM API dom_query](https://docs.rs/dom_query/0.28.0/dom_query/struct.Document.html);
метод `formatted_text`, который схлопывает пробелы, здесь намеренно не применяется.

## Сохраняемый документ

`page_document::normalize` создаёт собственный camelCase JSON `schemaVersion: 1`.
Идентичность `pageSource:1` вычисляется из типа источника и канонического выбранного URL
либо нативного opaque origin выбранного файла. Fragment URL не меняет ID страницы;
изменение содержимого меняет SHA256 оригинала, но не ID источника. Web и saved-page
используют разные пространства идентичности. Имя выбранного файла сохраняется точно и
не превращается в путь для повторного открытия.

В документ входят исходные байты UTF-8, их SHA256, версия извлечения, текстовая проекция,
metadata/ограничения и происхождение. Для выбранного URL сохраняются адрес выбора,
конечный адрес, цепочка переходов и время получения. Для сохранённого файла время сетевой
загрузки не выдумывается. Указанное издателем время публикации остаётся отдельным полем.

Новый документ проверяется на лимит 32 MiB с учётом JSON-экранирования без выделения
второго буфера. Превышение отвергается до сохранения: исходник не обрезается.
`page_document::decode` применяет тот же лимит, отвергает неизвестную версию,
посторонние/повторные поля, legacy aliases и отсутствующие обязательные `null`-поля.
Из оригинала заново вычисляются ID, SHA256, текст и metadata. Несовпадение отвергается;
сохранённые данные при этом не перезаписываются. Проверка URL здесь только структурная,
без DNS или сети: public-address policy выполняется при получении страницы.

Декодер не подтверждает подлинность получения и не выдаёт доступ. Вызывающий native
сценарий должен сначала проверить текущий grant, принадлежность снимка и hash ревизии
корпуса. Сохранённые локальные страницы подключены к durable queue и подготовке эпизодов;
CorpusPort и UI ещё не завершены.

## Предпросмотр сохранённого файла

`preview_ingestion_page` / `IngestionPort.previewSavedPage` принимают выданный нативным
picker `sourceHandle`, явный MIME HTML/plain/Markdown и бюджет. Путь, origin, имя,
авторство и grant не принимаются от frontend. Используется закреплённый файловый
дескриптор и точное имя выбора; неподдерживаемое UTF-8 имя отклоняется, а не подменяется.

Чтение ограничено меньшим из input budget и лимита парсера 4 MiB, учитывает EOF,
контрольную сумму, отмену и время всего предпросмотра. Размер JSON документа с
экранированием проверяется против бюджета порции. Нормализация не изменяет исходник.
После полного чтения сохраняется schemaVersion 3 preview receipt с
SHA256/размером и одним ресурсом: source key, точный title либо имя файла, оценка одного
документа. Версия 3 включает проверенный opaque origin и точное имя файла, чтобы
worker мог восстановить исходную идентичность после перезапуска и явного повторного
выбора перемещённого файла. Эти метаданные входят в hash receipt; путь для открытия
не сохраняется. Тело страницы в предпросмотр не записывается. Неподтверждённые author labels
не превращаются в author IDs; предпросмотр сам не выдаёт разрешений на корпус, модель
или экспорт. Повторный импорт требует отдельного подтверждения области доступа.

Адаптер — `savedPage:1:selectedPageText:1:domQuery0.28.0:html5ever0.39.0`; форматы —
`savedPageHtml`, `savedPageText`, `savedPageMarkdown`. Операция регистрируется как
`savedPage`, чтобы отмена/очистка соответствовала сервису. Ассоциация native handle с
receipt использует общий механизм Telegram с rollback при ошибке сохранения. UI выбора,
получение URL в общий preview ещё не подключены.

Предпросмотры версий 1 и 2 читаются по прежним правилам и с прежним hash; их байты и
поколение не мигрируют при чтении. Telegram продолжает писать версию 2 без поля `origin`.
Добавление `origin` даже со значением `null` к старой записи отвергается. Версия 3 требует
поддерживаемый формат страницы, соответствующий origin source key и отсутствие
неподтверждённых author IDs. Неизвестные версии и повреждения не перезаписываются.

## Очередь сохранённых страниц

Общий сценарий выбирает адаптер по проверенному durable preview и сверяет provider
операции с этим адаптером. Создание binding, запуск, повтор, восстановление и запрос
снимка используют тот же provider; выбор адаптера не поступает отдельным флагом UI.
Прежние Telegram JSON preview/worker продолжают работать с их версиями.

`ingestion-page-worker` сначала проверяет текущие разрешения и отдельно фиксирует
предпросмотр и grants в контрольных точках. Затем полностью читает выбранный файл с
ограничениями предпросмотра, сверяет SHA256/длину/source key и только после этого
сохраняет один `PageDocument`. Каждая запись и финальная публикация повторно проверяют
разрешения, отмену и оставшееся время. Общая база независимо измеряет сохраняемые
байты, включая metadata/provenance, против бюджетов порции и задания.

Исходная страница и извлечённый текст входят в одну неизменяемую ревизию; provenance
содержит `savedPage`, точную длину оригинала и явное отсутствие provider object ID.
Страница без подтверждённого author ID попадает только в разрешённый неизвестный
контекст и выбранный период. Неизвестная дата требует `includeUndated`. Ни имя файла,
ни author label не превращают документ в собственные слова Персоны. Исключённый
фильтрами документ даёт завершённое задание с нулевым покрытием, а не выдуманный текст.

Loaded coverage не означает indexed/analyzed/used: эти счётчики остаются нулевыми.
Завершённый оригинал публикуется через общий `corpus:<jobId>` / `import:<jobId>` receipt;
повтор завершённого задания возвращает тот же снимок. Ошибка чтения может быть
повторяемой, но изменившийся исходник, отмена, отозванный grant и превышенный бюджет
не публикуют частичный снимок. После перезапуска требуется новый native picker handle;
проверенное восстановление перемещённого файла сохраняет исходные origin и имя.
Контрольная точка не содержит путь для автоматического открытия.

Синтетические native fixtures проверяют точный оригинал с Unicode/CRLF, отдельную
проекцию, подмену файла, ошибку чтения после сохранения grants, повтор без дублей,
перемещение до первой порции, период/неизвестного автора, лимиты и отмену/отзыв/срок
в конце чтения. Это ещё не завершение `proteus-tip.7`: URL, Instagram, GitHub,
пользовательский выбор и полная интеграция CorpusPort остаются незавершённой работой.

## Подготовка и поиск страниц

Завершённое задание выбирает свой native-кодек через общий `CompletedAdapter`.
Перед чтением оригиналов проверяются текущие grants, provider операции, версия
адаптера, полный checkpoint и принадлежность исходного снимка. Кодек страницы
повторно проверяет точный origin/имя, MIME, SHA256/длину, идентичность документа и
provenance. Изменённый, перепривязанный или выданный за другой формат оригинал
не становится материалом подготовки.

Подготовка использует `savedPagePreparation:1`, сохраняя старый
`telegramPreparation:1` и его идентификаторы. Эпизод страницы сохраняет binding,
исходную ревизию и отдельный conversation key. Источник не меняет роль Reference
на Own. Chunk spans относятся к проверенной текстовой проекции: это байтовые
смещения в `PageDocument.text`, а не позиции в HTML. Оригинал остаётся доступным
в той же неизменяемой ревизии при отдельной проверке прав.

Отдельный анализ известных маркеров связей использует тот же ограниченный HTML-
парсер. Ссылки `a/area[href]`, `blockquote`, `q`, `cite` и citation microdata,
распространённые кавычки, Markdown-скобки/цитирование и явные URL консервативно
означают неразрешённую связь. Автоматического обхода адресов и выдуманных связей нет.
Такие страницы остаются вне reference-раздела. Страницы без даты также изолированы
существующей политикой эпизодов, даже если `includeUndated` разрешил их загрузку.
Для датированной страницы без известных маркеров работает обычное детерминированное
разбиение. Точные копии текста сохраняются и связываются общей политикой разделения.

Анализ не доказывает отсутствие непомеченных заимствований и не решает произвольные
частичные совпадения: расширение overlap-политики относится к `proteus-tip.8`.
Признак известных маркеров существует только во внутреннем результате парсера;
он не меняет JSON `PageDocument` версии 1, текст, hash или сохранённые оригиналы.

Нативный FTS индексирует только подготовленные reference-фрагменты. Query проверяет
актуальный индекс и права Персоны; отмена, истечение/отзыв grant, другой provider
операции и удаление источника не обходятся успешным старым receipt. Эти операции
не дают права на модельную обработку или экспорт. Подключение к MemoryPort и UI
остаётся последующей интеграцией общего релиза.

## Native URL preview

`preview_ingestion_url` accepts one explicit URL and a bounded budget, never a caller-supplied body, origin, identity or grant. The shared public HTTP reader checks DNS and each redirect; preview limits acquisition to 4 MiB and 60 seconds (or the smaller requested budget). The canonical envelope must also fit the requested batch/expanded budget. The original, MIME, exact selected/final URL, redirects, retrieval time and digest are retained in a volatile native capability, with at most eight selections and 32 MiB of original/metadata bytes in total. Each selection permits at most 16 preview associations. Derived text is not retained in this registry.

URL preview metadata uses storage version 4 (`web`, `selectedUrlHtml`/`selectedUrlText`/`selectedUrlMarkdown`); saved-page writers remain version 3. Earlier preview identities stay unchanged. Metadata includes one resource, its exact title or selected URL, original fingerprint and origin, without source body or inferred author identity. The opaque `url:` handle is released explicitly or when a late/cancelled IPC response is discarded; failed persistence releases the registry entry. Preview does not authorize model processing or export and does not claim corpus loading/indexing. The page queue's URL worker, restart/refetch flow and source-picker UI are still pending.
