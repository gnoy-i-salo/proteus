# Требования и реализация PROTEUS

Исходные материалы: [архитектура](https://www.figma.com/board/3hiDci4IiVhc7rSTiErcol/PROTEUS?node-id=0-1), [компоновки экранов](https://www.figma.com/board/3hiDci4IiVhc7rSTiErcol/PROTEUS?node-id=2-2832), [общие пожелания](https://www.figma.com/board/3hiDci4IiVhc7rSTiErcol/PROTEUS?node-id=2-2572). Дополнительные условия: модели в настройках приложения, установленные Codex/Kimi CLI, игровой стиль по [In The Weights](https://intheweights.com/), отсутствие прокрутки.

Версия 0.2 сохраняет сущности и технические границы исходного решения. Согласованное изменение алгоритма заменяет спекулятивный BSC на оценку выполнения задачи, добавляет протокол, нейтральный контроль и явное представление неопределённости. Ни BSC v1, ни BSC v2 не являются измерениями интеллекта реального человека.

## Алгоритм и честность результата

| Требование                      | Реализация и проверяемое поведение                                                                                                     |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Сохранить сущности              | STALKER, Person Fabric, Person, Brain Scoring и Brain Analyzator остаются отдельными доменными пакетами                                |
| Критерии до ответов             | Brain Analyzator создаёт рубрику только из общей задачи; UI показывает протокол до исследования персон                                 |
| Фиксированный протокол          | Критерии, веса, обязательность, настройки, повторы, порядок и версия промптов сохраняются вместе с результатом                         |
| STALKER без задачи              | Получает только исходные сведения о персоне; не прогнозирует интеллект, BSC или effort                                                 |
| Факты и гипотезы                | Evidence содержит URL, выдержку, статус, происхождение и ограничения; пользовательский контекст остаётся непроверенной гипотезой       |
| Нет ложной верификации          | `model-reported` не означает независимую проверку; момент загрузки источника неизвестен и хранится как `null`                          |
| Связи с источниками             | Правила и task-skills ссылаются на существующие evidence IDs; гипотезы не повышаются до `supported`                                    |
| Недостаток и конфликт данных    | `unknown`/`conflicting` не используются как основание поведенческого правила; отсутствие supported-правил даёт синтетический профиль   |
| Отдельная адаптация             | Базовый профиль формируется без задачи; затем обе персоны и контроль получают общую адаптацию с одинаковым requested effort            |
| Нейтральный контроль            | Решает ту же задачу с одинаковыми запрошенными настройками Person; resolved-model неизвестна; проходит адаптацию без персональных черт |
| Повторы без смены профиля       | Один разведочный или три повторных прогона; исходный профиль и task-skills между ними фиксированы                                      |
| Баланс порядка                  | При трёх повторах участники последовательно занимают каждую из трёх позиций                                                            |
| Слепая оценка                   | Судья получает задачу, рубрику и тексты с временными labels, без имён, профилей, метрик, провайдеров и reasoning исполнителей          |
| Проверка зависимости от порядка | Каждая тройка ответов оценивается в прямом и обратном порядке с корректным обратным сопоставлением участников                          |
| Наблюдаемое основание оценки    | Каждая оценка содержит статус и обоснование; `met`/`partial` требуют буквальную цитату из ответа                                       |
| BSC v2                          | Детерминированная взвешенная оценка 0–100; `unknown` и расхождения дают диапазон, все критерии остаются в знаменателе                  |
| Обязательные условия            | Высокий общий балл не компенсирует провал обязательного критерия; неполнота и неизвестность сохраняются                                |
| Агрегирование                   | Медианы границ и разброс прогонов, evaluated/planned, разногласия и прохождение обязательных условий показываются отдельно             |
| Сравнение                       | Разницы в баллах между персонами и относительно контроля; отсутствие достаточных оснований не заменяется уверенным победителем         |
| Отдельные затраты               | Время и технические повторы не меняют качество ответа; `active-reasoning-ms` неизвестно                                                |
| Ограниченная интерпретация      | BSC зависит от рубрики и судьи; три прогона не доказывают статистическую значимость, профиль не доказывает точную симуляцию человека   |

Регрессии алгоритма находятся в `packages/stalker`, `person-fabric`, `person`, `brain-scoring`, `brain-analyzator` и `pipeline`. Перечень инвариантов и формула приведены в [архитектуре](architecture.md). Наличие тестов не заменяет результаты конкретного CI-запуска.

## Приложение и технические границы

| Требование                             | Реализация и проверка                                                                                                               |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| SolidJS, TypeScript, SCSS Modules, FSD | Desktop; AST-проверка границ, TypeScript, ESLint, Stylelint                                                                         |
| pnpm монорепозиторий                   | Девять приватных workspace-пакетов `@proteus-int/*`, включая desktop                                                                |
| Архитектура как проверяемая модель     | LikeC4, согласование manifests, импорты через публичные API, отсутствие циклов                                                      |
| Настройки моделей                      | На каждый из четырёх модельных компонентов, общий apply-all, alias; Brain Scoring без выбора модели                                 |
| Реальные провайдеры                    | Вызовы установленных Codex/Kimi CLI через Rust IPC; отсутствие настройки даёт явную ошибку                                          |
| Авторизация CLI                        | PROTEUS не читает/копирует токены, не хранит ключи во frontend                                                                      |
| Один executable                        | Встроенный frontend; отдельный Node-сервер приложения не нужен                                                                      |
| Ограниченные инструменты               | Поиск только STALKER; отключённые shell/multi-agent Codex, явный tool allowlist Kimi                                                |
| Traces                                 | Только reasoning, опубликованный CLI; ответ и stderr не подменяют reasoning; усечение отмечается                                    |
| Честные метаданные                     | Requested model/effort отделены от наблюдённых значений; неизвестные resolved model, версия CLI и active reasoning — `null`         |
| Отмена/ошибки                          | Дальнейшие этапы прекращаются, дерево активного CLI завершается, фиктивные ответы/баллы не создаются                                |
| Исправление формата                    | Одна повторная генерация ответа этапа после ошибки схемы; содержание может измениться, обе попытки учитываются отдельно от прогонов |
| Экран протокола                        | Просмотр критериев, весов и условий перед запуском исследования и ответов                                                           |
| Основные экраны                        | Ввод/протокол, выполнение, анализ с sidebar и сравнением                                                                            |
| Без прокрутки                          | Пагинация длинных полей, журнала, reasoning и ответов; e2e проверяет overflow                                                       |
| Внешний вид                            | Бирюзовая/фиолетовая палитры, серый центр логотипа, pixel font, ступенчатые тени, пиксельные кнопки окна                            |
| Нативное окно                          | Без рамки, drag/minimize/maximize/close; минимум 640×600                                                                            |
| Публичные ссылки                       | До пяти отдельных полей на персону, валидация публичных URL, без локальных адресов и паролей                                        |
| Сохранение                             | Локальный JSON v2, протокол, профили, ответы, оценки, traces и артефакты персон; ошибки записи явные                                |
| Версионирование                        | `schema-version: 2`, `scoring-version: 2`; старые результаты не пересчитываются и не сравниваются напрямую с новыми                 |
| Пресеты                                | `.proteus` v1 сохраняется: две персоны и задача, максимум 128 КиБ; системные диалоги и ассоциации файлов                            |
| Безопасный импорт                      | Импорт сам не запускает модели, при активном эксперименте откладывается, повреждённый файл не заменяет ввод                         |
| Релизы                                 | Проверки перед сборкой четырёх установщиков, затем публикация и SHA-256 через GitHub Actions                                        |
| Рабочий цикл                           | TDD, негативные fixtures harness, атомарные Conventional Commits, Husky и Beads по `AGENTS.md`                                      |

## Ограничения, которые остаются явными

- Публичный URL, цитата и правильная схема JSON не доказывают достоверность источника или соответствие человека профилю.
- Обезличивание известных идентификаторов не гарантирует устранение косвенных идентифицирующих признаков.
- Слепые перестановки снижают один вид смещения оценки, но один LLM-судья остаётся ограниченным оценщиком. Независимая проверка человеком или предметным тестом не включается автоматически.
- Три повтора относятся к одной задаче и зафиксированному профилю. Они не дают общего рейтинга способностей и не проверяют устойчивость построения профиля на разных источниках.
- Wall time зависит от CLI, сети, ожидания провайдера и длины ответа; оно не является активным временем reasoning.
- Kimi 2.3.2 в используемом режиме `stream-json` не публикует thinking. Интерфейс явно показывает отсутствие reasoning; ответ и stderr не используются вместо него.
- Неполные сведения о фактической модели/версии CLI ограничивают воспроизводимость. Пустые значения не заменяются предполагаемыми.
- Нативное сохранение ограничено 8 МиБ на результат; превышение даёт явную ошибку без молчаливого усечения.
- macOS-релиз использует ad-hoc подпись без notarization, Windows — без сертификата издателя; ОС может запросить разрешение на запуск.

Статус текущего кандидата и платформы описаны в [release notes](release-notes.md), команды проверок и рабочий цикл — в [harness](harness.md).
