# Подключение источников в PROTEUS

Откройте настройки → «Подключения». Параметры сервисов вводятся в desktop; они не нужны GitHub Pages. Для эксперимента с подключённым источником выберите Codex во всех компонентах: Kimi пока не обеспечивает подтверждённого отключения пользовательских hooks при обработке такого материала.

## Telegram

1. Войдите в [my.telegram.org](https://my.telegram.org) и откройте **API development tools**.
2. Создайте приложение и сохраните выданные `api_id` и `api_hash` в настройках Telegram в PROTEUS.
3. Нажмите «Войти по QR-коду». На телефоне откройте Telegram → Настройки → Устройства → Подключить устройство и отсканируйте QR в PROTEUS. Код обновляется автоматически. Если Telegram запросит пароль двухэтапной проверки, введите его в PROTEUS.
4. Запасной вариант — «Войти по номеру телефона», затем код и пароль при необходимости. Во время QR-входа кнопка явно отменяет текущую попытку и начинает вход по номеру. Если QR только что подтверждён на телефоне, дождитесь результата в PROTEUS, прежде чем отменять эту попытку. Приложение использует встроенную TDLib.
5. В источнике Персоны укажите `@channel_name`, ссылку `https://t.me/channel_name` или числовой ID доступного чата. Для выделения конкретного участника укажите его ID и нужный период.

Регистрацию и параметры описывает [официальная инструкция Telegram](https://core.telegram.org/api/obtaining_api_id). Доступная сессии история может быть неполной; приложение сохраняет ограничения покрытия.

## VK

1. Зарегистрируйте Web-приложение VK ID. Название PROTEUS подходит.
2. Укажите доверенный Redirect URI: `https://gnoy-i-salo.github.io/proteus/auth/` — с завершающим `/`.
3. Для предоставленной регистрации Client ID `54881156` уже подставлен в PROTEUS; при необходимости замените его своим. Сохраните настройку, нажмите «Войти в VK через браузер», завершите вход в браузере и вернитесь кнопкой на странице callback.
4. Источник: `id12345` или конкретная запись `wall12345_678`. Доступ к данным определяется правами приложения и аккаунта; успешный VK ID вход сам по себе не гарантирует доступ к стене и комментариям.

Если вкладка закрыта, нажмите повторное открытие браузера: действующая попытка входа сохраняется. Если она истекла, начните вход заново.

Полная таблица полей кабинета и протокол возврата находятся в [auth.md](auth.md). Секрет приложения в SPA не добавляется.

## GitHub

1. В GitHub Settings → Developer settings → GitHub Apps создайте приложение.
2. Включите **Device flow**. Для нужных репозиториев выдайте только необходимые права чтения, например Contents, Issues и Pull requests, и установите приложение на выбранные репозитории.
3. В PROTEUS сохраните **Client ID**, затем подтвердите показанный код в браузере. Client ID отличается от App ID.
4. В источнике укажите `owner/repository` или ссылку на корень репозитория. Автор материала задаётся отдельно: владение репозиторием не означает авторство всего его содержимого.

Доступ ограничен пересечением прав пользователя и приложения. Подробности — [официальный GitHub device flow](https://docs.github.com/en/apps/creating-github-apps/authenticating-with-a-github-app/generating-a-user-access-token-for-a-github-app#using-the-device-flow-to-generate-a-user-access-token).

## Instagram и файлы

Нажмите «Открыть экспорт Instagram» — приложение откроет [Центр аккаунтов](https://accountscenter.instagram.com/info_and_permissions/dyi/) в системном браузере. Выберите свой Instagram-профиль → экспорт на устройство → нужные сообщения и период → формат JSON. При изменении страницы путь в настройках Instagram: Центр аккаунтов → Ваша информация и разрешения → Экспорт информации.

Дождитесь подготовки и скачайте архив. Для личных диалогов используйте импорт своего экспорта: распакуйте архив и выберите поддерживаемый JSON или текстовый файл через системное окно PROTEUS. Приложение показывает предупреждения о пропущенных вложениях и неподдерживаемых полях. Импорт файла сам по себе не запускает передачу в модель.

Для собственного Business/Creator аккаунта можно сохранить токен, выданный Instagram API setup в Meta App Dashboard. Он обрабатывается и хранится нативно. Это персональная настройка профессионального API, а не универсальный вход в произвольные личные аккаунты. Автоматический скраппинг и общий Instagram OAuth с серверным секретом в эту версию не входят.

## Выбор материала для Персоны

После подключения добавьте источник к нужной Персоне: ресурс, автора, период и разрешение на обработку указанным модельным провайдером. Grant ограничивает чтение и срок действия; skill не может расширить его. Изменение Персоны, preset или модельных настроек требует повторного выбора.

Кнопка «Удалить материалы STALKER» удаляет локальный корпус выбранного сервиса и его checkpoints. Подключение и отдельная база TDLib этим действием не удаляются.

Исходные документы хранятся зашифрованно локально. В модель передаются разрешённые ограниченные фрагменты с исходными именами, идентификаторами авторов, ссылками, адресами и handles. Текст и оформление не обезличиваются. Обработка через настроенный модельный провайдер может передавать эти данные за пределы компьютера; она требует отдельного разрешения.

Ответы отображаются как симуляция с сохранёнными сообщениями, пробелами и переносами. Отчёт содержит происхождение и ограничения; он не обещает копию мышления 1 в 1. Точные образцы речи по умолчанию не разрешены для экспорта. Экспортированный JSON версии 3 явно отмечает редактирование и то, что оценки относятся к исходному прогону.
