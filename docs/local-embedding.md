# Локальный CPU runtime E5

`local_embedding::runtime::E5Runtime` выполняет inference на CPU через Candle
0.11.1 (F32). Native-слой включает проверяемый кеш модели и версионированное
хранилище векторов. Подключение к MemoryPort, пользовательскому управлению моделью
и итоговый RU benchmark ещё нужны.
Сценарий, вызывающий адаптер, обязан отдельно проверить разрешение на обработку
текста моделью. Загрузка файла сама по себе такого разрешения не даёт.

Единственный pin — `scripts/e5-embedding-package.json`: multilingual-e5-small,
revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`, 384 измерения. Перед чтением
тензоров проверяются точные размер и SHA256 конфигурации и весов. Токенизатор
использует тот же revision и собственную проверку checksum. Fingerprint включает
все pins, runtime, pooling/normalization и fingerprint токенизатора с версиями
query/passage templates. Несовпадение ожидаемого профиля отклоняется до inference.

`pnpm prepare:models` готовит токенизатор; `pnpm prepare:embedding-model` явно
получает публичные веса и config для native-тестов. Обе команды проверяют SHA256,
не заменяют повреждённый cache и не оставляют частичный пакет. Файлы находятся в
игнорируемом `.cache/models`; веса не входят в Git и пока не включаются в app bundle.
Приложение не скачивает их автоматически. Runtime читает только переданные локальные
пути. Отсутствующий/повреждённый пакет возвращает типизированную причину недоступности;
облачного fallback, случайных или нулевых заменителей векторов нет.

Каждая последовательность ограничена 512 токенами, batch — 8 элементами и 4096
**padded** токенами. Маска строится по длинам: CLS с ID 0 не является padding.
Pooling — masked mean с накоплением f64 и L2 normalization; выход проверяется на
размерность и конечность. Исходные строки корпуса не изменяются.

Минимальная заявленная RAM reservation — 1536 MiB. Это предварительный допуск
к выполнению, а не OS-ограничитель RSS; суммарный лимит нескольких runtime должен
обеспечивать владеющий сценарий. Cancellation, отзыв разрешения и deadline проверяются
при чтении файлов, между токенизацией, inference и pooling. Текущий Candle forward
не прерывается посередине; результат после истечения бюджета не возвращается.
Это ограничение необходимо учитывать до подключения пользовательских операций.

Изолированный feasibility probe на macOS arm64, CPU F32, 2 потока: загрузка около
3713 ms, batch четырёх коротких passage около 47 ms, четырёх query около 37 ms,
peak RSS около 1029 MiB. Четыре синтетических русских retrieval-примера дали top-1
4/4, нормы и независимость от padding проверены. Это одиночное наблюдение небольшого
прототипа, не p50/p95, не максимальная RAM и не гарантия качества retrieval. Оно
не заменяет измерения итогового приложения на всех целевых платформах.

Native unit-тесты используют реальные закреплённые веса: проверяют размерность,
норму, padding, mismatch профиля, бюджеты, отмену и повреждённые файлы. CI и Release
явно готовят пакет до `pnpm check:rust`; отрицательные harness fixtures запрещают
пропуск подготовки и рассогласование runtime/model revision. FTS остаётся независим
от embedding weights. Полная приёмка tip.10 остаётся открытой до готовности
интеграции, управления ресурсами и измерений.

Cargo dev/test профиль явно оптимизирует ядра SHA256 (`sha2`), как и Candle;
release уже использует оптимизацию. Холодный запуск проверяет файл весов в кеше и при загрузке runtime;
неоптимизированный software SHA256 сам может исчерпать бюджет операции. Замер
09.11.2026 на macOS arm64 для закреплённых 470641600 байт: два прохода занимали
25,409/26,586 с без оптимизации и 1,428/1,423 с при `opt-level = 3`, с одинаковым
ожидаемым SHA256. Это проверка сохранения результата, не обещание времени для
других машин. Лимиты времени, повторная проверка целостности и отмена сохранены.

Native `local_embedding::cache::install_verified_artifact` проверяет и устанавливает
один закреплённый файл из переданного reader в локальный кеш по SHA256. Он не
скачивает модель: транспорт остаётся ответственностью сценария управления моделью.
Чтение ограничено порциями 1 MiB, проверяются точная длина,
checksum и отмена, включая EOF при повторном использовании существующего файла.
Проверенный временный файл публикуется через hard link; одновременные установки
одного pin проверяют уже опубликованный файл. Повреждённый существующий кеш
сохраняется и явно отклоняется, каталоги, symlink и другие не-обычные файлы
не принимаются за модель. Ошибка чтения или отмена не удаляют прежний хороший файл.

Временные файлы удаляются после нормального завершения/ошибки; аварийное завершение
может оставить временный каталог, очистка которого относится к сценарию запуска.
Защита от процесса с теми же правами ОС не заявлена; crash-durability зависит от ОС,
синхронизация каталога выполняется best-effort на Unix. Эта функция ещё не является
EmbeddingPort или пользовательским экраном установки.

`local_embedding::manager` объединяет три закреплённых файла в пакет. Native
`runtime::cache_descriptor()` получает pins из тех же спецификаций, что и inference,
и проверяет общую revision токенизатора и весов. Просмотр кеша ничего не создаёт;
готовность требует проверки всех трёх файлов. Повреждённая часть явно отклоняется,
даже если другая часть отсутствует. Установка открывает reader только для
отсутствующего файла и держит не более одного reader; проверенные части остаются
для повтора после сбоя. Прогресс считает только проверенные файлы и байты. Отмена,
включая последний callback прогресса, не возвращает успешный результат. Пути
остаются внутри native-слоя; скачивание и IPC/UI этим модулем не реализованы.

`local_embedding::search::search` выполняет точный cosine scan независимого
семантического списка. Алгоритм проходит iterator ссылок на векторы и сохраняет
только до 1000 лучших результатов и множество проверенных IDs (до 100000).
Вариант `search_stream` принимает краткоживущие строки базы; хранением и памятью
входного вектора управляет reader. Размер отдельного вектора —
1..4096 значений; текущий E5 producer выдаёт 384. Нормы и скалярные произведения
накапливаются в f64. Разные fingerprints/размерности, нечисловые значения, нулевые
нормы, повторные IDs и превышение бюджета отклоняют всю операцию. Равные оценки
упорядочиваются по точному ID; отмена проверяется между кандидатами и перед возвратом.
Эта функция не загружает весь corpus и не фильтрует кандидатов совпадениями FTS.

Входные кандидаты уже должны быть ограничены текущими grants, persona, reference
и периодом в native host. Численный алгоритм не является разрешением на чтение;
после поиска host обязан повторно проверить доступ. Хранилище и чтение векторных
кандидатов описаны ниже; подключение к MemoryPort ещё не реализовано.

Воспроизводимый синтетический probe находится в
`apps/desktop/src-tauri/src/e5-retrieval-observations.rs`: 16 реплик, восемь запросов,
десять повторов. Есть близкие отвлекающие реплики, отрицание, похожие номера заказов
и русскоязычный запрос к англоязычной реплике. Он использует настоящие закреплённые
веса и точный cosine scan; печатает ранги ожидаемых документов, top-1, recall@3,
MRR, загрузку и время batch из восьми query вместе с поиском. Тест проверяет
повторяемость, но не задаёт желаемый порог качества: неудачные ранги тоже наблюдения.
Это небольшой контролируемый пример, не оценка полного корпуса или сходства Персоны.

```sh
RAYON_NUM_THREADS=2 cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml \
  synthetic_ru_retrieval_observations_use_real_pinned_vectors -- --nocapture --test-threads=1
```

Для RSS запускать уже собранный test executable под системным измерителем памяти,
чтобы не смешивать память компилятора и модели. Профиль тестов, число потоков, ОС,
число кандидатов и размер batch нужно сохранять вместе с результатами. p50/p95
здесь относятся к десяти целым query batches, а не к отдельному запросу; percentile
использует nearest-rank. Это dev/test профиль с оптимизированными Candle kernels,
а не latency установленного release-приложения.

Наблюдение 08.11.2026, macOS 26.6 arm64, `RAYON_NUM_THREADS=2`, test профиль:
fingerprint `e5Embedding:1:ce3c9eddb139e3fdec09a40bee4fa020b2daf24abac421137630f67050e9559b`.
Ранги `[1, 1, 1, 1, 1, 1, 1, 2]`: top-1 **7/8**, recall@3 **8/8**, MRR **0.9375**.
Русский запрос к английской реплике оказался на втором месте. Загрузка — 24965 ms,
два passage batches — 15118 ms, query+search batch p50 — 5607 ms, p95 — 5670 ms.
Суммарный test process — 96.5 s. Отдельный снимок процесса во время выполнения
показал RSS 889056 KiB (около 868 MiB); это **не peak RSS**. Системный измеритель
peak RSS не получил доступ к `kern.clockrate`, поэтому максимум памяти не заявлен.
Результаты dev/test не сопоставимы напрямую с предыдущим optimized feasibility
probe и не доказывают улучшение относительно FTS или другой модели.

`retrieval_ranking::fuse` объединяет независимые лексический и семантический списки
по reciprocal-rank fusion (`k=60`, ранги от 1), затем ограничивает число результатов
из одного документа. Допускается до 1000 кандидатов в каждом списке и до 100
результатов; одинаковый chunk объединяется один раз, конфликт его document ID
отклоняется. Равные оценки упорядочиваются по chunk ID. Пустой семантический список
сохраняет честный lexical-only режим. Параметр `k=60` — фиксированный baseline,
а не результат подбора на этом синтетическом probe. Функция не проверяет grants
и не расширяет эпизоды: оба списка уже должны быть разрешены host, который повторно
проверяет доступ перед выдачей исходного текста. Внешнее расширение эпизодов,
retrieval receipts и интеграция MemoryPort ещё нужны.

## Durable vector generation storage

Schema v6 stores vectors in the same encrypted corpus database. Native storage
entry points begin/resume an exact stage, append one finite nonzero f32 vector
with an explicit matching model fingerprint, then publish only when every chunk
in the pinned FTS generation is present. Replays compare exact little-endian
bytes, including signed zero. Source publication drift fails before mutation.

Publication streams rows in binary chunk-ID order, hashes a versioned length-
prefixed model/dimensions/ID/vector representation, seals the generation and
switches the active pointer in one transaction. It never copies the full vector
set. Cancellation checks run before work, for every publication row and before
commit. A replay of an older sealed receipt cannot move the active pointer back.
Encrypted reopen tests cover interrupted staging and exact receipt replay.

These storage primitives do not authorize model processing or provide retrieval.
The native caller must check current grants before embedding and through the
checkpoint callback. Host authorization, bounded abandoned-stage cleanup, model management and
worker/MemoryPort integration remain required release work.

## Scoped native reads

Lexical search, reference-chunk enumeration and exact vector search share one
SQL scope filter (snapshot/generation, persona, grants, bindings and period).
Reference enumeration has no lexical query: keyset pages select at most 100
metadata rows before fetching exact text within the remaining byte budget
(maximum 64 MiB/page, 4 MiB/chunk). Missing or oversized stored text is an error;
a next chunk that does not fit remains behind the returned cursor.

Vector reads pin the full active vector receipt and its current FTS source in a
read savepoint. Unfinished or stale source generations cannot serve semantic
hits. A complete scope is applied before ranking. The SQL query streams vectors
without sorting their blobs; deterministic cosine ordering and tie breaks belong
to the bounded ranker. One row buffer can be dropped after each callback; a
storage, profile, cancellation or candidate-budget error discards all partial
hits. At most 100000 candidate IDs and 1000 result references are retained.

These database primitives do not issue grants. The native orchestration below
supplies scope and live permission checks; production MemoryPort sessions, bounded
episode expansion and retrieval receipts still need integration and acceptance.

## Индексирование разрешённого корпуса

`ingestion::vectors::build` связывает завершённую native-задачу, подготовленный
снимок и локальный embedding-адаптер. Общий `IndexAuthority` используется также
лексическим индексированием и поиском; он проверяет владельца снимка, живые grants
и полный receipt. Для векторного построения отдельно требуется model-processing
permission всех выбранных привязок и совпадение токенизатора подготовки с моделью.

Текст читается порциями до восьми reference-чанков и 32 MiB. Inference выполняется
вне блокировки базы; до, во время и после него проверяются отзыв доступа, отмена,
deadline и текущий индекс. Публикация требует полного набора векторов исходного
receipt. Незавершённая стадия сохраняется: повтор проверяет прежние строки и
вычисляет только отсутствующие; опубликованная стадия возвращает тот же receipt
без повторного inference. Отложенные данные не передаются модели. Общий лимит RAM
для нескольких runtime, запуск из IPC/UI, очистка старых стадий и MemoryPort
остаются ответственностью интеграционного сценария.

## Гибридный поиск в разрешённом снимке

`ingestion::hybrid_query::query` получает независимые списки FTS и exact cosine,
объединяет их RRF и ограничивает число результатов одного документа. Смысловое
совпадение может попасть в результат при отсутствии любых словесных совпадений.
Область выводится из завершённой задачи: persona, пары grant/binding, снимок,
поколение и период применяются до ранжирования. Оба индекса должны соответствовать
одному полному source receipt, а токенизатор и embedding fingerprint — модели.

До query inference требуется действующее разрешение обработки моделью. Inference
не удерживает блокировку базы; источник, разрешения и срок проверяются через
callback и после вычисления. Отзыв разрешения, перестроение индекса или отмена
перед возвратом отклоняют весь результат. Нет автоматического перехода в FTS-only:
лексический сценарий вызывается отдельно и не требует embedding weights.

Ограничения одного вызова: до 100 кандидатов в каждом списке, до 100000 сканируемых
векторов, до 100 результатов, до 64 MiB точного текста и до 60 секунд кооперативного
бюджета. Чтение выбранных chunk IDs сохраняет порядок рангов и проверяет область
в той же транзакции, что и полный receipt. Отсутствующая/чужая ссылка или нехватка
байтов отклоняют весь запрос. Исходные Unicode, пробелы и переводы строк сохраняются.

Интеграционный тест проходит путь выбранного архива через подготовку, FTS,
настоящую закреплённую E5 и гибридную выдачу. Проверки дополнительно покрывают
semantic-only результат, holdout, период, stale generation, отзыв разрешения во
время inference и последнюю границу отмены. Это получение кандидатов, ещё не
`MemoryPort`: cumulative budgets сессии, расширение эпизодов, проверяемые citations
и окончательный latency benchmark остаются обязательной работой tip.11.

`ingestion::episode_read::read` расширяет отдельный reference-эпизод в пределах
той же native-задачи. Произвольный ID не заменяет проверок persona, binding,
model-processing grant, подготовленного снимка и текущего FTS receipt. Перед
чтением оригиналов проверяются ссылки эпизода и область всех его чанков; после
чтения — точные spans, текст, текущие разрешения и отмена. Holdout, чужой эпизод,
устаревшее поколение, неполный набор чанков или недостаточный бюджет дают ошибку
вместо частичного результата.

Хранилище переиспользует проверку закреплённого preparation cursor и общие ссылки
на оригиналы/эпизоды внутри страницы. Случайное чтение не сдвигает последовательный
курсор. Ограничены число чанков, байты исходного текста, объём сохранённых данных
одной страницы и время. `context_tokens` здесь — сумма сохранённых token counts
закреплённого E5-токенизатора; это не измерение токенов Codex/Kimi. Возвращаемые
оригиналы остаются внутренними Rust-объектами. Разрешённые excerpts проецируются
отдельно; IPC ещё не подключён.

`memory::session::MemorySession` закрепляет завершённую задачу, persona, период,
полный source receipt и разрешение model-processing при создании. Модель может
предложить запрос или ID эпизода. После отзыва разрешения или изменения индекса сессия
закрывается; следующий вызов не перепривязывает её к новому источнику.

Общий ledger ограничивает попытки, выданные чанки, эпизоды, байты, сохранённые E5
token counts и срок всей сессии. Ошибочный ID тоже расходует попытку; запрещённый
до начала вызов не запускает чтение. Завершившийся результат учитывается и
возвращается только после повторной проверки живых разрешений, receipt, времени
и отмены. Исчерпанный бюджет останавливает последующие вызовы до обращения к
хранилищу. Дополнительно одно чтение ограничено 100 чанками, 16 MiB сохранённых
страниц и 60 секундами. Создание сессии также расходует её общий срок.

Лексическая сессия создаётся через `bind`, гибридная — через `bind_hybrid`, который
закрепляет полный vector receipt и профиль локальной модели. Режим нельзя поменять
внутри вызова. Отсутствие весов или замена поколения векторов не приводят к
автоматическому переходу в FTS-only. `recall` и `read_episode` используют один
ledger; выдача содержит реальные эпизоды, исходные spans и сохранённые token counts.
Поиск ограничен десятью кандидатами на список и двумя выдаваемыми чанками документа;
остаток бюджета может уменьшить выдачу. Сканирование векторов отдельно ограничено
100000 строк на запрос; счётчик candidates учитывает выданные reference-чанки.
Повторные выдачи повторно расходуют лимиты. Это внутренний native-сценарий:
он не создаёт вымышленные MemoryItems из найденного текста. IPC,
выдача citations через IPC и публикация памяти остаются частями интеграции MemoryPort.

`recall_recorded` и `read_episode_recorded` создают native-квитанции версии 2
из результата той же сессии. ID создаётся хостом; policyVersion берётся из
разрешённых bindings, а snapshot/generation, spans, ранги и счётчики — из
проверенного чтения. Расширение эпизода имеет null ranks и нулевой fusionScore.
Гибридная квитанция описывает реальные закреплённые weights/tokenizer hashes,
нормализацию, шаблоны и chunking version; чужой runtime fingerprint отклоняется.
Перед выдачей квитанции доступ, отмена и время проверяются повторно. Квитанция
остаётся аудитом чтения, а не правом на новый вызов модели или доказательством
анализа источника: однократный model-context lease связывает её с точным
входом, а успешный native CLI dispatch отдельно отмечает завершение.

`memory::registry::MemorySessions` хранит до 16 сессий под случайными native ID.
Неизвестный или занятый ID отклоняется до чтения источника; разрешение проверяется
перед действием и выдачей результата. Реестр не держит общий lock во время работы.
Закрытие немедленно отзывает handle и отменяет операцию без ожидания занятой сессии;
её ресурсы продолжают занимать место в лимите до завершения worker. Shutdown
отменяет все сессии и запрещает новые. Реестр зарегистрирован в приложении и
используется CLI; команды открытия и действий MemoryPort ещё не подключены.

Сессия сохраняет не более 1000 выданных квитанций и 16 MiB их сериализованного
JSON, включая метаданные и экранирование. Возвращаемый результат и сохранённая
квитанция разделяют неизменяемые данные. Повторное использование принимает только
уникальные ID этой сессии и снова проверяет живые разрешения; ID другой сессии
не становится доступным даже для той же персоны и снимка.

`prepare_research_input` собирает исследовательский вход из сохранённых квитанций
в Rust. Исходные system prompt и префикс задачи сохраняются; после задачи добавляется
помеченный JSON-контекст версии 1 с точными источниками. Размер готовой задачи
ограничен существующими 200000 байтами CLI, system prompt — 40000; переполнение
отклоняется без усечения. Хост вычисляет hash контекста и точного полного входа,
повторно проверяет доступ после сборки. Этот подготовленный вход пока не расходует
бюджет модельных вызовов и сам по себе не разрешает запуск CLI.

Native-сессия отдельно принимает однократную настройку исследовательской модели
и `ModelCallBudget`. `reserve_research_context` сохраняет собранный вход под
случайным ID и сразу учитывает попытку и байты; исправляющий вызов тоже расходует
бюджет. `consume_model_context` требует точного входа, provider/model/effort/operation
и нового invocation ID. Повторное использование отклоняется. Срок модельных вызовов
проверяется независимо от бюджета поиска, без повторного списания при завершении.

Только завершённые вызовы могут дать `completed_context_receipts`: неиспользованное
резервирование и одно лишь потребление не доказывают анализ. Повторяющиеся квитанции
объединяются; разрешение и срок проверяются перед выдачей подтверждения. Ошибка
последней проверки закрывает модельный ledger. CLI принимает `memoryContext` с
нативными `sessionId` и `leaseId`: неизвестная сессия, чужой lease, подмена точного
входа или выбранной модели не допускаются. После проверки возможностей CLI, перед
записью/отправкой prompt, lease потребляется один раз. Доступ и модельный срок
проверяются перед запуском процесса, отправкой текста, во время ожидания и перед
выдачей ответа. Отзыв source grant останавливает работающий процесс. Завершение
отмечает только native dispatch после успешного кода выхода и валидного ответа;
отдельной frontend-команды завершения нет. Старые CLI payload без расширения
сохраняют совместимость; legacy writer отклоняет новый контекст вместо потери ID.
`completed_context_audit` возвращает версионированные camelCase-метаданные только
завершённых вызовов: native lease/invocation ID, выбранную модель и режим,
SHA256 и размер точного входа, SHA256 контекста, упорядоченные ID квитанций,
номер попытки и время завершения по проверенным native-часам. Повторное чтение
не меняет время; текст prompt и источников в журнал не копируется. Перед выдачей
снова проверяются source grant и модельный срок. Это ещё не durable-публикация:
сохранение журнала вместе с памятью должно выполняться одной транзакцией.
Команды MemoryPort, TS lease DTO, frozen manifest для Person и сохранение
подтверждённого покрытия остаются незавершёнными.

`verify_research_support` сверяет элементы с квитанциями только завершённых
контекстов этой сессии. Фрагмент должен входить в реально переданный reference
текст и сохранять границы UTF-8; episode ID выводится из native-квитанции. Для
`observed` и `styleExample` необходим точный цитируемый текст выбранного автора,
без пересылок, цитат и смешанного авторства. `reportedAssertion` не становится
`observed`. Проверка отдельно возвращает переданные модели и использованные в
элементах spans, удаляя повторы без изменения исходного текста. Это проверка
оснований, не подтверждение истинности сообщения и ещё не сохранение публикации.
Финальная проверка сессии учитывает и source grant, и модельный срок: истечение
последнего во время обработки не позволяет вернуть успешное подтверждение.

`memory::research_draft` декодирует `ResearchPublicationDraft` версии 1 с точным
набором camelCase-полей и обязательным nullable `eventAt`. Черновик ограничен
1000 элементами и 16 МиБ кодированного JSON; лимит действует и для native typed
входа без выделения второй копии JSON. Общие проверки текста, spans и дат
переиспользуют владельца persisted DTO. Ссылки противоречий различают уже
опубликованные элементы и другие черновики текущей партии; повторы, ссылки
на себя и отсутствующие draft ID отклоняются. Сборка `MemoryBundle` принимает
отдельную native-идентичность: ID, время и policy не читаются из черновика,
текст и метаданные источников не нормализуются. Это структурная сборка;
завершённые контексты, живые права, существование опубликованных противоречий
и транзакционное сохранение обязан проверить сценарий публикации.

`CorpusDatabase::publish_research_checked` сохраняет MemoryBundle и журнал
исследования одной IMMEDIATE-транзакцией в существующей схеме 7. Журнал версии 1
содержит квитанцию публикации, native-квитанции retrieval и завершённых контекстов,
а также хеш канонического черновика; тексты prompts и оригиналов не дублируются.
Точный повтор идемпотентен, конфликт не перезаписывает данные. Проверки отмены
до commit откатывают обе части; после commit нет callback, который мог бы
сообщить ложный откат. Reader проверяет размер до чтения JSON, SHA256, версии,
ссылки, владельца, состав памяти и неизменяемый исходный snapshot. Удаление
источника каскадно удаляет журнал; прежние bundles без журнала остаются читаемыми.
Это native storage API, а не новая IPC-команда: живые права, происхождение
покрытия и подготовка публикации из завершённых контекстов ещё требуют подключения
сценария MemorySession.

`ingestion::source_excerpt` — общий владелец проекции для recall и чтения эпизода.
Он повторно сверяет исходный документ с адаптером и выбранной областью, проверяет
UTF-8 границы и выдаёт только точный текст span. `document.contentHash` относится
к полному декодированному тексту; сам полный текст и grant не сериализуются.
Имена, название источника, исходный формат, ID объекта и ограничения сохраняются
в `sourceMetadata` версии 1. Несколько авторских подписей страницы остаются
отдельными строками без вымышленного author ID; неизвестная дата чтения архива
остаётся `null`, URL использует фактическую дату загрузки.

Чужие слова, пересылки, цитаты и неоднозначные связи не подтверждают собственную
речь персоны. Известный reply ID сохраняет пространство имён адаптера в `replyTo`;
если эта проекция не разрешила конкретную ревизию или автора связи, поля
`relations.original`/`originalAuthor` остаются неизвестными. Совпадение текста
цитаты не доказывает её автора. Это ограниченная проекция с сохранением originals,
не полная гидратация связанных документов. Проверки живых разрешений и бюджета
выполняются после проекции перед возвратом результата.

## Загрузка закреплённого пакета

`local_embedding::download::install_pinned_package` получает native-дескриптор
из того же владельца pins, что и проверка кеша. Адреса трёх файлов выводятся из
публичного model ID и закреплённой revision на Hugging Face; произвольного URL во
frontend API нет. Разрешено до пяти HTTPS-переходов. Транспорт не передаёт
credentials, cookies или заголовки авторизации и не использует системный proxy.

Одновременно читается одно HTTP-тело через ограниченный буфер существующего
проверяющего кеша. Объявленная длина сверяется до чтения тела; фактическая длина
и SHA256 — до публикации файла. Проверенные файлы повторно не загружаются,
прерванная попытка сохраняет готовые артефакты для повтора. Повреждённый существующий
файл остаётся на месте и даёт явную ошибку.

Отмена и общий deadline проверяются между чтениями. Уже начатое чтение ограничено
тайм-аутом операции reqwest; мгновенная отмена и жёсткий лимит RSS не заявляются.
Причина отмены сохраняется дословно и не может ошибочно превратиться в deadline;
тайм-аут тела и ошибки ОС различаются. Проверки используют маленькие локальные
HTTP-фикстуры, без реальной загрузки весов. Автоматический фоновой запуск отсутствует.

`LocalModelService` выбирает каталог внутри native app cache и владеет одним
`RuntimeSlot<E5Runtime>`. Проверка пакета, загрузка и inference используют общий
эксклюзивный доступ без очереди; повторный inference переиспользует проверенную
модель в RAM. Состояние RAM и проверка файлов на диске разделены. Освобождение
модели допускается только между операциями. Заявленный resident budget проверяется
и при повторном использовании, но не является жёстким ограничением RSS.

IPC предоставляет состояние, явную проверку/загрузку пакета, отмену по точному ID
и освобождение RAM. Путь, URL, профиль модели и текст для inference из этого API
не принимаются. Загрузка ограничена 30 минутами, подключение — 10 секундами,
HTTP-запрос — 30 секундами; инспекция — 60 секундами. Счётчик прогресса отражает
полностью проверенные файлы, а не число уже скачанных байтов. Закрытие приложения
просит остановить текущую работу и ожидает её завершения. Source-сценарии передают
собственную живую проверку разрешений до/после работы. Общий срок `with_runtime`
включает загрузку модели и callback; ограничения отдельных inference сохраняются.

Отмена и публикация кешированного runtime согласованы одним mutex: подтверждённая
отмена не превращается в успешный результат. Уже начавшийся Candle forward
завершается до следующей проверки. Прикладные IPC-сценарии индекса/MemoryPort
ещё должны подключить сервис; наличие команды загрузки само по себе их не завершает.

Настройки → Модели → Локальный поиск управляют проверкой/загрузкой пакета и
освобождением RAM. Открытие читает только метаданные; файлы проверяются отдельно,
загрузка требует явного действия. Web preview сообщает о native-ограничении.
Адаптер сверяет версию, operation ID и счётчики с размером закреплённого пакета,
подписывается на прогресс до загрузки и снимает подписку при завершении.
Отмена до native admission повторяется раз в 100 мс, без параллельных запросов,
до подтверждения или завершения worker. Интерфейс ожидает сам worker и игнорирует
поздние результаты после закрытия панели; повтор не удаляет проверенные файлы.

Перед повторной явной загрузкой сервис в том же эксклюзивном maintenance-слоте
очищает остатки прерванной установки: только каталоги `.artifact-install-` с 16
строчными hex-символами, пустые либо содержащие один обычный файл `artifact`.
Рекурсивного удаления нет; неизвестные файлы, ссылки и опубликованные SHA-имена
сохраняются. Обход ограничен 1024 записями и 128 временными каталогами. Проверка
отмены выполняется и между удалением файла и пустого каталога; повтор завершит
такую частичную очистку. Произвольные изменения другим процессом с теми же правами
ОС остаются за пределами этой гарантии. Открытие настроек и inspect ничего не удаляют.
