# Страница возврата VK и GitHub Pages

`apps/auth` — статическое SolidJS-приложение для HTTPS callback VK ID. Оно проверяет форму ответа, удаляет query и fragment из текущей записи истории, затем по нажатию пользователя открывает фиксированную ссылку PROTEUS. Desktop принимает callback, проверяет одноразовый state и срок жизни, затем обменивает код с PKCE в Rust. Для реального входа необходимо зарегистрировать приложение VK и сохранить его Client ID в настройках PROTEUS; опубликованная страница сама по себе аккаунт не подключает.

## Значения для кабинета VK

| Поле                                              | Значение                                      |
| ------------------------------------------------- | --------------------------------------------- |
| Платформа                                         | Web                                           |
| Адрес сайта                                       | `https://gnoy-i-salo.github.io/proteus/`      |
| Базовый домен, если поле требует только имя хоста | `gnoy-i-salo.github.io`                       |
| Доверенный Redirect URI                           | `https://gnoy-i-salo.github.io/proteus/auth/` |

Сохраняйте завершающий `/` в Redirect URI. Не добавляйте `#/callback`, параметры, `localhost` или `proteus://` в HTTPS redirect кабинета. Физическая страница `auth/index.html` обслуживает callback без правил перенаправления SPA. После обновления страницы полученный код уже очищен: повторное подключение начинается из desktop.

Client ID предоставленной регистрации PROTEUS — `54881156`. Поле desktop предварительно заполнено им; сохранённое пользовательское значение имеет приоритет. Вход запускается только явным нажатием.

Номер приложения VK указывается в настройках подключения desktop. Он не нужен для публикации callback; секрет приложения не добавляется в SPA или GitHub Pages.

## Протокол возврата v1

Общий парсер `parseVkAuthCallback` экспортируется из `@proteus-int/contracts`. Вход успешного callback: `code`, `device_id`, `state`; допустимые метаданные `type=code_v2`, `expires_in`, `ext_id` проверяются и не пересылаются. Выход — фиксированная ссылка `proteus://oauth/vk?v=1&code=…&device_id=…&state=…`.

Для ошибки VK принимаются `error`, `state` и необязательный `error_description`. Сайт не показывает и не пересылает исходное описание: desktop получает `access_denied` или `provider_error`. Неизвестные поля, токены, дубликаты, неоднозначные ответы, повреждённое кодирование, управляющие символы и превышение ограничений отвергаются. Ответ во fragment не принимается. При невозможности очистить адрес кнопка возврата не появляется.

SPA проверяет только структуру. Нативный обработчик проверяет `v`, схему, host/path, ожидаемый provider и state, срок жизни, однократность и сохранённые параметры транзакции. Только Rust выполняет обмен с PKCE verifier. Параметры callback не могут менять endpoint, client ID, redirect URI или запускать операции без pending-транзакции.

Страница не запускает приложение автоматически и не утверждает, что вход завершён. Нажатие означает попытку открытия PROTEUS; результат знает desktop. Секреты, verifier и токены в SPA отсутствуют; код ответа остаётся только в памяти вкладки до закрытия/обновления. Короткоживущий код проходит через инфраструктуру HTTPS-хостинга, поэтому очистка истории не означает удаления журналов хостинга.

В production действуют CSP без сетевых API-запросов и ранний `no-referrer`. Шрифт, логотип, JavaScript и CSS размещены вместе с приложением. Нет аналитики, cookies, браузерного хранилища или service worker. Страница работает вне привилегированного окна Tauri.

## Сборка и публикация

```sh
pnpm dev:auth                  # локальная разработка, порт 1421
pnpm check:package auth        # пакет и зависящие пакеты
pnpm test:e2e --project auth   # браузерные проверки production-сборки
pnpm build:pages               # единый артефакт .cache/pages
```

Если локального Chromium нет, используйте `PLAYWRIGHT_CHANNEL=chrome`. Сборка `build:pages` содержит `/auth/`, `/architecture/`, стартовую страницу и `build-info.json` с SHA исходного коммита. Исходники, `.env` и рабочая директория целиком не публикуются; ссылки на внешние файлы в сборках отвергаются.

В настройках GitHub Pages источником выбираются GitHub Actions. Workflow `.github/workflows/ci.yml` собирает сайт; публикация разрешена только для `trunk` после успешных quality, native и pages-build. PR собирает сайт без публикации. Деплои сериализованы; новый push в `trunk` не прерывает выполняющийся workflow публикации. Сайт выкладывается одним артефактом, чтобы auth и LikeC4 не перезаписывали друг друга.

При изменении домена или имени репозитория одновременно обновляются base приложения, base LikeC4 в сборке, браузерные проверки, этот документ и зарегистрированный redirect VK. Desktop открывает браузер явной кнопкой «Войти в VK через браузер». Повторное открытие использует только действующую нативную pending-транзакцию; callback SPA не создаёт её самостоятельно.

После деплоя проверяются HTTPS-адрес callback, загрузка локальных ресурсов, отказ некорректного callback и совпадение `build-info.json` с опубликованным коммитом. Эти проверки не заменяют полный OAuth-тест с зарегистрированным пользовательским приложением.
