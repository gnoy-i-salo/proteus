# Ограниченный виртуальный ZIP-ридер архивов

`apps/desktop/src-tauri/src/archive-zip.rs`, `archive-zip-directory.rs` и `archive-zip-input.rs` —
общая контейнерная основа для импорта архивов VK (и повторно используемая
для IG/TG). Модуль превращает переданный вызывающей стороной поток
`Read + Seek` в допущенный, ограниченный бюджетами виртуальный список файлов
и точное потоковое чтение выбранных записей. Это только контейнер: разбор
VK-HTML, JSON, grants, очередь импорта и UI остаются у своих владельцев.

## Границы модуля

- Модуль **никогда** не открывает пути вызывающей стороны и не превращает
  имена записей в пути файловой системы; вложенные архивы не следуются,
  вложения не загружаются.
- Имена и содержимое записей проходят побайтово без изменений: никакой
  нормализации, анонимизации и подмены исходного текста.
- Читатель работает только с одним контейнером за попытку; после любой
  структурной ошибки, превышения бюджета или сбоя чтения он помечается
  как отказавший (`Poisoned`) и отказывает в дальнейшей работе.
- Отмена и дедлайн — кооперативные: вызывающая сторона передаёт callback
  `FnMut() -> Result<(), String>`, который проверяется до и во время
  чтения каталога порциями, между записями и порциями распакованных байтов, а также перед возвратом успеха. Разбор уже замороженного ограниченного каталога внутри ZIP-библиотеки проверяется до и после; callback не прерывает её внутренний вызов. `Err` от callback прерывает попытку с
  `ArchiveZipError::Cancelled`; прерванная попытка считается завершённой.

## API

```rust
let limits = ArchiveZipLimits::default(); // или явный набор бюджетов
let (mut reader, listing) =
    ArchiveZipReader::open(capability, &limits, &mut interrupt)?;
for entry in &listing.entries {
    // entry.path, entry.is_directory, entry.compressed_size, entry.declared_size
}
reader.stream_entry(index, &mut interrupt, &mut |chunk| {
    // Сохранить временную порцию (до 64 KiB), ещё не публикуя результат.
    stage(chunk)
})?;
// Только теперь можно завершить временную запись.
let bytes = reader.read_entry(index, &mut interrupt)?; // вариант с полным Vec в памяти
```

- `ArchiveZipLimits::validate` отклоняет нулевые/неполные бюджеты до любого
  чтения (`InvalidLimits`).
- `ArchiveZipReader::open` возвращает ридера и `ArchiveZipListing`
  (`entries`, `raw_bytes` — измеренная длина потока, `metadata_bytes` —
  суммарный размер центрального каталога по заголовку).
- `read_entry` отдаёт только полностью и точно прочитанную запись; обрыв,
  CRC-несовпадение или превышение размера дают ошибку, частичный результат
  никогда не выглядит успехом.
- `stream_entry` не собирает запись целиком: потребитель получает порции до 64 KiB. Они предварительные: ошибка CRC, несовпадение итогового размера, отмена или ошибка потребителя завершают попытку без успеха; частично записанное staging-содержимое должен отбросить вызывающий код. `read_entry` — удобный вариант для небольших записей, выделяющий память до принятого лимита записи.
- Аксессоры: `entry`, `entry_count`, `metadata_bytes`, `expanded_bytes`.

## Бюджеты (`ArchiveZipLimits`)

| Поле                       | Что ограничивает                                                   | Этап   |
| -------------------------- | ------------------------------------------------------------------ | ------ |
| `max_archive_bytes`        | Сырые байты всего потока                                           | допуск |
| `max_entries`              | Число записей центрального каталога                                | допуск |
| `max_metadata_bytes`       | Суммарные байты центрального каталога                              | допуск |
| `max_entry_expanded_bytes` | Фактически расширенные байты одной записи                          | чтение |
| `max_total_expanded_bytes` | Сумма фактически выданных байт (повторные чтения считаются заново) | чтение |
| `max_compression_ratio`    | Отношение расширенных к сжатым байтам записи                       | чтение |

Допуск заголовков выполняет отдельный ограниченный preflight
(`archive-zip-directory.rs`) **до** того, как ZIP-библиотека строит индекс:
в zip 9.4.2 выделение под записи производится из недоверенных полей EOCD
(`IndexMap::with_capacity`, `Vec::with_capacity`), а родной предел
`isize::MAX` практической защитой не является. Preflight разбирает EOCD
(и валидную пару ZIP64 EOCD/locator при переполненных ZIP32-полях) обычными
`Read`/`Seek`, проверяет бюджеты и структурные инварианты, и только затем
`archive-zip-input.rs` копирует только допущенный центральный каталог в ограниченную память. Проверка дубликатов и ZIP-библиотека читают одну неизменяемую копию; повторного чтения недоверенных EOCD-полей из изменяемого файла нет. Внутренний виртуальный поток завершается минимальной канонической парой ZIP64/ZIP32 с проверенными размерами, без комментария; каталог непосредственно прилегает к этой паре. `ZipArchive::with_config(Known(0))` поэтому не может перейти к другой вложенной EOCD-сигнатуре при ошибке каталога. Исходный файл, имена и содержимое записей не переписываются; комментарий всего архива API не выдаёт. Содержимое читается из исходной capability, без копирования всего архива; его конечный SHA256 и неизменность для публикации проверяет владелец ingestion-попытки. Сам контейнер не является grant или гарантией неизменяемого источника. Все размеры — `u64` с checked-
арифметикой; заголовочные размеры никогда не считаются доверенной длиной
записи. Ранние выходы по заявленным размерам — консервативная экономия,
учёт ведётся по измеренным распакованным байтам, итоговая длина должна точно совпасть с объявленной. Сжатый диапазон обязан целиком предшествовать центральному каталогу. Знаменатель compression ratio — объявленная длина этого ограниченного диапазона, а не число байтов, фактически потреблённых Deflate до его EOF; отдельные лимиты распаковки действуют независимо.

## Форматные ограничения (явные)

- Поддерживаются однотомные незашифрованные ZIP32 и ZIP64 (satellite-поля
  ZIP64 в записях допускаются библиотекой; preflight требует корректной пары
  locator/record, когда ZIP32-поля EOCD переполнены). Многотомные и
  spanned-контейнеры отклоняются явно.
- Переполненные ZIP32-поля без ZIP64-записи — `InvalidArchive`.
- Методы сжатия: только Stored и Deflate; прочее — `UnsupportedFormat`.
- Зашифрованные записи (ZipCrypto/AES) — `UnsupportedFormat`.
- Символические ссылки и не-регулярные Unix-типы (fifo, устройства, сокеты)
  — `UnsupportedFormat`. Unix-режим берётся из external attributes
  версий, записанных Unix-хостом; `unix_mode == None` трактуется как
  обычный файл (архивы Windows-инструментов).
- Директории определяются **только** завершающим `/` и не имеют содержимого;
  попытка чтения директории — явная ошибка. Несовпадение Unix-режима
  каталога с завершающим `/` отклоняется как неоднозначность.
- Кодировка имён — строгий UTF-8 поверх сырых байтов центрального каталога;
  CP437/legacy-декодирование не реализовано (экспорты VK/IG/TG — UTF-8),
  lossy-подстановка не выполняется никогда. Невалидное имя —
  `InvalidEntryName`.

## Виртуальный путь

Имя допускается только если оно: непустое; без NUL; без `\`; не начинается с
`/`; без префикса диска (`C:`); при разбиении по `/` не содержит пустых
компонентов, `.` и `..`. Нарушения — `InvalidEntryName`. Две записи с
одинаковым именем — `DuplicateEntryPath` (обнаруживается обходом сырого
центрального каталога: индекс zip 9.4.2 молча отбрасывает дубликаты).

## Ошибки

`ArchiveZipError` различает `NotZip`, `InvalidArchive` (структура),
`UnsupportedFormat` (формат), `InvalidEntryName`, `DuplicateEntryPath`,
`InvalidLimits`, `BudgetExceeded(&'static str)` с меткой бюджета
(`archive_bytes`, `entry_count`, `metadata_bytes`, `entry_expanded_bytes`,
`total_expanded_bytes`, `compression_ratio`), `EntryReadFailed`,
`Cancelled`, `Io` и `Poisoned`.

## Зависимости

Только `zip = "=9.4.2"` с `default-features = false` и read-фичей
`deflate-flate2-zlib-rs` (чисто-Rust inflate; write-side zopfli не нужен).
`serde`/`sha2` не требуются. Регистрация модуля и интеграция манифеста —
владение основного агента. Модуль зарегистрирован в native executable; специализированный VK-парсер и очередь импорта остаются отдельной работой.
